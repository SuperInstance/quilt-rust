# quilt — Node.js binding (the web/connecting tier's runtime)

A thin [koffi](https://koffi.dev) FFI binding over the quilt C ABI
(`crates/quilt-cabi/quilt_cabi.h`, backed by `libquilt_cabi.so`) — pure
passthrough, never reimplementing the engine or the ledger. This
completes the FFI binding set: Python / Go / Julia / R / Lua / **Node**.

```
one native core  →  libquilt_cabi.so  →  this binding  →  JS
```

## Why the C ABI path (and how the .wasm fits in)

The task allowed either artifact. The choice is the **native C ABI via
koffi**, for one structural reason: `quilt-core-wasm` deliberately
exports only two C-ABI anchors — `quilt_core_wasm_abi_version()` and
`quilt_core_wasm_golden_check()` — a sealed 0/1 self-check (its real JS
surface is future wasm-bindgen work, per its own `lib.rs`). The C ABI is
the designed full binding surface for language runtimes (its header
literally lists "Node FFI"), and is the only path that exposes enough
surface to reproduce each golden op with **observable outputs**: cell
values, entry seals, the `chain_hash` string, reconcile reports.

The `.wasm` artifact is still exercised: `test.mjs` instantiates
`target/wasm32-unknown-unknown/release/quilt_core_wasm.wasm` with Node's
built-in `WebAssembly` and requires `golden_check → 1` — the same
golden contract self-verifying inside V8, from the same process that
just proved the native path. Two artifacts, one contract, one script.

`koffi` is the single third-party dependency (Node has no built-in FFI).

## Layout

| file | role |
|---|---|
| `quilt-ffi.mjs` | the loader/binding: library discovery, symbol protos, memory discipline, `Engine` class, ledger functions |
| `test.mjs` | golden conformance harness (ops a–e + wasm cross-check), PASS/FAIL + chain_hash |
| `package.json` | `npm test` → `node test.mjs` |

## Run

```bash
# artifacts (from the repo root, once):
cargo build -p quilt-cabi --release
cargo build -p quilt-core-wasm --release --target wasm32-unknown-unknown

# binding:
cd bindings/node
npm install            # koffi only
node test.mjs          # or: npm test — runs from anywhere
```

Expected tail:

```
RESULT: PASS — 36 checks, 0 failures
chain_hash: 4a7ad64830d5c2a843bf7b6f4d7253d43f2603753611fe58f0bb7c4d87ea62b8
```

Library resolution: `$QUILT_CABI_SO` if set, else walk up from this
directory to the repo root's `target/release/libquilt_cabi.so`.

## Memory discipline (per `quilt_cabi.h`)

- Borrowed `const char *` arguments: koffi encodes JS strings to
  NUL-terminated UTF-8 for the duration of the call only.
- Returned `char *` strings: every string-returning symbol is bound with
  a `void *` prototype so the pointer survives; the bytes are copied out
  byte-wise (UTF-8-safe), then released with `quilt_string_free()` —
  never `free()`, and never a second call of a side-effecting symbol
  (e.g. `quilt_ledger_record`) just to re-read its return.
- Engine handles are opaque and caller-owned (`e.free()`; use
  try/finally — see `test.mjs`).
- `quilt_last_error()` is borrowed: copied out immediately, never freed.

## Number-literal fidelity (why `test.mjs` has a JSON parser)

The golden contract's canonical JSON pins *integers as integers, floats
as shortest-round-trip (ryū)*. `JSON.parse` in JS loses `40.0` → `40`,
which would change every hashed byte and break every seal. The harness
therefore parses `compat/golden.json` with a tiny recursive-descent
parser that preserves number **literals** verbatim (`JNum`) — the file is
machine-generated by serde/ryū, so its literals are already canonical —
and `canon()` emits them unchanged. (JS number→string is coincidentally
also shortest-round-trip, but the int/float distinction is the part
`JSON.parse` cannot carry.)

## Known native quirk discovered by this binding

`quilt_last_error()` **violates its own header contract** on a thread
where no error was ever set: it returns
`RefCell<String>::new().as_ptr()` — `String::new()`'s dangling
non-null pointer (`1`) — instead of a valid pointer to `""`.
Dereferencing it segfaults (any FFI, not just koffi). Bindings that only
call `last_error` on failure paths (Python ctypes, etc.) never trip it.

`lastError()` in `quilt-ffi.mjs` guards this: pointers `0` and `1` are
treated as `""` and never dereferenced. Recommended fix in
`quilt-cabi`: return a `CString` (always allocated, even empty), or
`b"\0".as_ptr()` for the empty case.

## Notes

- `node_modules/` is git-ignored; do not commit it (`npm i` is only
  needed for koffi).
- Op (c) propagation is implied by op (b)'s reactive post-push reads,
  exactly as in the other tier harnesses; the C ABI does not expose
  dependency-graph introspection (that is engine-internal).
