### **Test 1: M01 – Rewrite Order (Dotted ID References)**
**Goal:** Verify that after a `set` operation, a formula referencing a short ID should read the updated value. The M01 bug causes short IDs to be rewritten inside longer IDs, corrupting dotted references.

```python
# Initial state
a = 10
b = 20
c = 30

# Formula: "a.b + c" (expects 10 + 30 = 40)
f = "a.b + c"

# Operation 1: get f → 40
print(f.get())  # Expected: 40

# Operation 2: set a = 100
a = 100

# Operation 3: get f → expects 130 (100 + 30)
print(f.get())  # Expected: 130
```

**Expected behavior:** 130  
**If M01 bug is present:** The rewrite process places `a` inside `b` (e.g., `a` becomes `b.a`). When `a.b` is evaluated, it tries to access `b.b`, which does not exist. The second `get` raises an error (e.g., `KeyError` or `IndexError`), demonstrating the corruption of dotted references.

### **Test 2: M05 – Cache Value Not Updated**
**Goal:** Verify that after a `set`, the cached value for a formula is updated. The M05 bug leaves the cache stale, causing incorrect results on subsequent reads.

```python
# Initial state
a = 10
f = "a + 10"

# Operation 1: get f → 20
print(f.get())  # Expected: 20

# Operation 2: set a = 100
a = 100

# Operation 3: get f → expects 110
print(f.get())  # Expected: 110
```

**Expected behavior:** 110  
**If M05 bug is present:** The cache for `f` still holds the old value (`20`). The second `get` returns `20` (stale) instead of `110`.

### **Test 3: M07 – Stale Dependency Marking**
**Goal:** Verify that after a `set`, a formula’s dependency is marked as stale. The M07 bug prevents the dependency from being marked stale, causing incorrect reads.

```python

# Operation 1: get f → 15

# Operation 3: get f → expects 110

```

**Expected behavior:** 110  
**If M07 bug is present:** After `a = 100`, the dependency `f` is marked **Ready** (no recomputation). The second `get` returns the stale value `15` instead of `110`.

### **Test 4: M06 – Wrong Sorting in min/max**
**Goal:** Verify that `min([a, b, c])` returns the smallest value. The M06 bug can cause `min` to return the largest value due to incorrect sorting.

**Expected behavior:** 10  
**If M06 bug is present:** The sorting logic may be reversed, causing `min` to return `100` (the maximum) instead of `10`.
